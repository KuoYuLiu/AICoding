完整版本（含流程圖與討論）在專案的 Claude Doc「程式學習AI助理：平台規劃文件 v2」。本檔是給開發時查閱的摘要，兩者不一致時以最新討論為準，並回頭更新本檔。

## 已確認的決策（2026-11-27）

| 項目 | 決定 |
| --- | --- |
| 第一個語言 | Python；架構保留多語言（語言設定檔 + 執行映像） |
| 對象 | 老師建立課程、匯入修課名單；學生在課程內寫作業 |
| 帳號 | 老師與學生都用 Google 帳號（Gmail）登入，依名單 Gmail 自動綁定 |
| 題目格式 | 比照 DOMjudge 題目包 |
| AI 助理 | 蘇格拉底式提問，五面向引導，不給答案；老師可自訂 prompt |
| AI 評分員 | 依五面向尺規評分並引用證據；老師確認後才公佈 |
| 截止未完成 | 自動以「未完成」送評分，「學習反饋」記 1 |
| 重做 | 老師在作業上設定，預設不可；開放時取最高或最後一次 |
| 試辦 | 大學一年級程式設計課 |
| 開發方式 | 一人搭配 Claude Code |

## 教師端功能

1. 匯入 DOMjudge 格式題目包（`problem.yaml`、`domjudge-problem.ini`、`problem_statement/`、`data/sample/`、`data/secret/`），匯入後用參考解答驗證測資。
2. 依題庫設定作業與繳交期限（指定班級或組別、遲交規則、個別延期）。
3. 建立多門課程，每門課有自己的語言設定、名單、作業、AI 設定；題庫可跨課程共用。
4. 上傳講義（PDF、PPTX、DOCX、Markdown）作為 AI 的參考來源，AI 回答時標出處。
5. 自訂 AI 助理 prompt（預設見 `prompts/assistant.md`），提供試聊、版本紀錄；平台安全規則不可刪除。
6. 設定 AI 評分員的評量尺規（預設見 `prompts/grader.md`），套用到作業後鎖定版本。
7. 審核 AI 評分：可修改或附註要求 AI 重改；確認後才公佈；保留所有版本。
8. 依老師勾選的欄位匯出 CSV 或 Excel，可儲存匯出範本。

## 學生端功能

1. 登入後進入課程、打開作業。
2. 解題畫面三欄：題目、程式編輯器與執行結果、AI 助理。
3. 編輯器禁止貼上，並記錄編輯歷程。
4. 透過與 AI 助理的對話逐步解題。
5. 依課程語言執行，錯誤訊息旁可請 AI 用中文解釋（不給修正後的程式）。
6. 「執行」跑範例測資，「提交測試」跑隱藏測資；全部通過後 AI 進行學習反饋，學生按「結束作答」後整個過程送交 AI 評分員。
7. 查看已公佈的評分等級、總分與回饋，可提出申訴。

## 階段路線

| 階段 | 範圍 | 關卡 |
| --- | --- | --- |
| 0 驗證原型（約 4 週） | 一題 Python 題目的完整流程：解題畫面、AI 助理、AI 評分、教師審核 | AI 沒有洩題；AI 評分與老師評分大致一致 |
| 1 MVP 單校試辦（約 12 週） | 教師端 8 項與學生端 7 項全部完成，只支援 Python | 大一課全班使用一學期，並至少另一位老師試用 |
| 2 商品化上市（約 12 週） | 個資合規、多校管理、AI 用量額度、評分可信度驗證、內建題庫、監控備份、Email 通知 | 第一批付費學校 |
| 3 擴充（持續） | 學習分析、Google Classroom 與 LTI 整合、相似度比對、考試模式、C 與 Java、學習歷程報告、本地部署 | — |

週數以每週 15 至 20 小時投入粗估。

## 主要風險

- 學生用提示詞「騙」出答案：三道防線（prompt 規則、輸出檢查、稽核）。
- AI 評分與老師判斷差距大：評分必引證據、校準範例、追蹤一致率。
- AI 用量成本高於定價：階段 0 先量測每題平均對話量。
- 整班同時提交造成執行排隊：佇列與壓力測試。
- 學生個資：最小化資料、送 AI 前去識別化。
